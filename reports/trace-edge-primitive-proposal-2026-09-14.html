A styling proposal for bbox-ui's edge primitive — 2026-09-14

Yes — you're in charge of all the styling. I pulled the actual source of React Flow UI's three edge recipes and re-read systemSketchArrow.tsx to check. Every one of them hands you a path and gets out of the way on the paint: the stroke colour, the dash pattern, the label's classes, the packet dot's fill are all hand-typed inline, never a design-system import. That's the whole argument for a Trace core, below.

tldraw's side agrees a different way: src/systemSketchArrow.tsx (your own repo) is 1,196 lines extending ArrowShapeUtil, and the entire reason it exists is that stock tldraw's getArrowInfo/getArrowBindings give you bindings and a route — never a packet cadence, a z⁻¹ pill, or the "before dashed / after dotted" split. You wrote DataCablePath, DelayedCablePaths, and DelayPill (blocks/connections/ConnectionShapeUtil.tsx:1857-2121) precisely because tldraw has the same gap React Flow does. Both hosts independently confirm the same line: path math is the engine's job; every pixel of paint is yours. That's exactly the core/adapter split ARCHITECTURE.md already draws for Block and Port — an edge primitive isn't a new kind of problem, it's the same rule applied to a third shape.

3. The split

Not a two-way split. Zach's own read on this, mid-review: "1 is edge design's appearance, the other thing is edge math, and like autoformatting/tidying stuff…" — the table below breaks that into five rows, not two, because "appearance" and "edge math" each split further once you ask who has to own them. Rows 2 and 3 matter most for his question, and — checking the actual SystemSketch files rather than assuming — neither one is cleanly on one side: row 2's authored-route editing is portable outright, and row 3 ("tidy") turns out to be the SAME split one level in — SystemSketch itself already keeps "collect obstacles from the live scene" (host) and "route around a given obstacle list" (portable, zero tldraw imports) in two separate files. The boundary was never "who wrote it" or even "which named feature," it's whether the math needs to see the rest of the canvas — a question you have to ask per FUNCTION, not per row.

Lives inOwns
1. Base path math — bezier/step/straight control points, arrow terminal binding host (React Flow core, tldraw ArrowShapeUtil) already solved, already a dependency, needs nothing but the two endpoints. Trace never computes a control point.
2. Authored route math — the multi-elbow case: dragging a corner, growing a new rail packages/bbox-ui/src/trace.routing.ts new Ours, and portable in principle — not a verbatim drop-in. Checked elbowAuthoredRoute.ts directly — resolveAuthoredRoute / moveAuthoredSegment / captureAuthoredRoute have zero tldraw imports. They operate on an AuthoredElbowRoute ({startAxis, points}) — a typed wrapper around a plain point array, not a raw array itself — and only need that route's own corners plus the two endpoints, never the rest of the canvas, which is the real line (§3's header). But captureAuthoredRoute returns a persisted ConnectionElbowRouteModel, and the module leans on SystemSketch's own ElbowRoute/ElbowSegment types — porting it to core means porting or replacing those types too, not copy-pasting the file. Still belongs beside the paint in core, not bolted to one host's handle system; a React Flow adapter could reuse the same edit functions to let someone drag a corner on a smoothstep edge.
3. Auto-tidy / obstacle avoidance — route around other shapes, spread channels split — see note Correction: this layer splits the same way layer 2 already suggested it might, and checking the actual files proves it. tidyEdges.ts does import Editor/TLShapeId, but it's orchestration only. The real work is two SEPARATE modules SystemSketch already keeps apart on purpose: routingObstacles.ts (own comment: "deliberately knows nothing about A*, nudging, persistence, or commands" — imports Editor, translates live Block/Branch shapes into plain rectangles) feeds collisionAwareRouting.ts (own comment: "Pure collision-routing phases" — ZERO tldraw imports, just A*/nudge/stabilize over ElbowRect/ ElbowRoutingObstacle DATA). So it's not "tidy is host-bound" — it's the exact same rule as layer 2, one level removed: gathering the obstacle list needs the live canvas (host, trace.routing.ts's adapter-side caller), routing around a given obstacle list doesn't (portable, belongs beside layer 2's functions in trace.routing.ts itself). An earlier draft of this table called the whole thing host-bound and would have duplicated the portable half in every adapter.
4. Paint — stroke, dash cadence, arrowhead marker, the label chip packages/bbox-ui/src/trace.tsx takes a finished path: string + length: number (from layer 1 and/or 2), renders SVG. Zero imports of either engine — same promise ARCHITECTURE.md makes for Port.
5. Interaction — click-to-select, hover, hit-testing width, which handle got grabbed host React Flow: its own selection path (see §4 below). tldraw: the ArrowShapeUtil's handles, exactly as systemSketchArrow.tsx already does today — it calls layer 2's pure functions FROM its own onHandleDrag, which is the seam: the drag EVENT is host-owned, the route MATH it feeds isn't.

One consequence worth naming: layer 2 does not belong in trace.fields.ts alongside variant/state/tone. A FieldSpec is a discrete, panel-editable value — a dropdown, a toggle, a slider. An authored route is a continuous point array a person drags on the canvas. bbox-ui's own /create bench makes this concrete: its inspector-column is a field-list editor, and its viewport already runs live React Flow and tldraw canvases. Route-dragging doesn't need a new panel row OR a new tab — once an adapter wires layer 2's functions into its own handle system, dragging a corner just works inside the canvas tabs that already exist. What's missing isn't a place to interact with it, it's a place to document it (a demo page, the way port.mdx documents Port's states) — a docs-site question, out of scope here.

The one wrinkle worth resolving now, not after

React Flow's BaseEdge is a convenience — it renders one <path>, wires markerEnd, and (per its own docs) adds an invisible wider hit-path for you. It is not required: an edge component can render any SVG it wants inside React Flow's <g class="react-flow__edge">, the same way systemSketchArrow.tsx 's own render function shows it CAN go either way per branch: most of its presentation branches keep <StockArrow> mounted (for binding, routing, labels, endpoint reflow — genuinely still tldraw's job) and layer an extra stroke on top; its one fully-detached (exact) branch skips the stock component entirely and paints only its own path. Both are real precedent for skipping BaseEdge below. So:

  • data / async — expressible as a single stroke → the adapter can still use <BaseEdge> for free hit-testing, and assembles its style object from THREE separate resolutions, carefully NOT spread together — className has to come back out before the rest goes in style, or it leaks into the CSS object as an invalid property. An earlier draft of this example got the colour step wrong THREE times over, each caught by a separate round of review: the resolver never took the caller's strokeColor override as input (decorative, do-nothing field — the exact "field with no visual consequence" trap appearance.ts's own LENS_BEFORE_FIELD comment warns about); bare paintVar() breaks on the real "transparent" member of PaintToken (produces invalid var(--transparent) — Pill goes through its own paintColor() wrapper instead, which special-cases "transparent" first); and once both of those were fixed, the spread order in the subject object was backwards — putting the raw strokeColor prop LAST unconditionally overwrites the tone override even when strokeColor is undefined, silencing `tone` whenever it's set without an explicit colour. Pill's real pillResolutionSubject spreads ...toneOverride(...) LAST for exactly this reason — tone must win over the raw prop, not the other way round. Also closing a real gap: the sketch never actually EXPORTED a resolver an adapter could call, so here's the missing piece, `resolveTraceStrokeColor` — the module-level function `trace.tsx` should export, spread order fixed, mirroring `pillResolutionSubject` exactly: 
    // The function itself takes RESOLVED values and never guesses a default —
// exactly like Pill's own render function, defaults live in the DESTRUCTURING,
// not sprinkled as `??` at every call site:
export function resolveTraceStrokeColor(variant: TraceVariant, tone: Tone, strokeColor?: PaintToken): string {
  const subject = { variant, strokeColor, ...toneOverride(tone, ["strokeColor"]) }; // tone LAST — it must win
  const token = resolveField(STROKE_COLOR_FIELD, subject, TRACE_PRESETS).resolved as PaintToken;
  return paintColor(token, 1);
}

// Inside the adapter's own edge component — `variant`/`tone` are ALREADY resolved
// here (defaulted once, on the way in), same as Pill's `{ state = "empty", tone = "neutral" }`.
// `edgePath` is React Flow's own math (§1), never Trace's; `markerEnd` is Trace's ABSTRACT
// "arrow"|"none" translated into RF's resolved marker object HERE, in the adapter — passing
// it through raw would be exactly the untranslated bug the marker table row (§5) warns against.
function BBoxTraceEdge({
  variant = "data", tone = "neutral", strokeColor, animated, markerEnd = "arrow",
  sourceX, sourceY, sourcePosition, targetX, targetY, targetPosition, length,
}: TraceProps & EdgeProps) {
  const [edgePath] = getBezierPath({ sourceX, sourceY, sourcePosition, targetX, targetY, targetPosition });
  const strokeColorResolved = resolveTraceStrokeColor(variant, tone, strokeColor);
  const { className, ...dash } = traceStrokeStyle(variant, length, animated);
  const rfMarkerEnd = markerEnd === "none" ? undefined
    : { type: MarkerType.Arrow, color: strokeColorResolved };
  return <BaseEdge path={edgePath} markerEnd={rfMarkerEnd} className={className}
    style={{ ...dash, stroke: strokeColorResolved }} />;
}

The DOM shape still differs per host (RF wraps a <BaseEdge>, tldraw draws its own <path>) — what's shared is the resolved values, not the wrapper markup.
  • delayed — needs two split paths + a pill, which BaseEdge can't express in one style object. Here the adapter renders <TraceBody> (the core's own multi-path SVG, ported straight from DataCablePath / DelayedCablePaths) directly, and adds its own thin invisible hit-path alongside for selection — a few lines, host-owned, exactly the interaction-geometry carve-out ARCHITECTURE.md already names.

4. API sketch

export type TraceVariant = "data" | "async" | "delayed";

export interface TraceProps {
  /** The finished path — a host computes this (getBezierPath, an elbow
   *  route, a tldraw PathBuilder). Trace never derives its own points. */
  path: string;
  /** Arc length of `path`, for dash-phase math (async centering, the
   *  delayed split). It is NOT the straight endpoint distance — a bezier
   *  curve is longer than the chord between its ends, and using the chord
   *  would misalign the async cadence. tldraw is inconsistent, not
   *  uniformly absent: checked tldraw's own arrow-types.ts —
   *  TLStraightArrowInfo.length is a real field, and
   *  TLArcArrowInfo.bodyArc.length exists too (both verified
   *  against tldraw's real .ts source, not just its
   *  .d.ts) — but TLElbowArrowInfo has no length
   *  field at all. RF's getBezierPath returns 5 values
   *  ([path, labelX, labelY, offsetX, offsetY]) and never has
   *  one, for any of its path types. Rather than branch per arrow type per
   *  host, Trace picks ONE uniform, host-agnostic measurement:
   *  SVGPathElement.getTotalLength() on the mounted
   *  <path> — exact, and it doesn't care whether the
   *  host had a length lying around or not. The real wrinkle:
   *  getTotalLength() needs a MOUNTED element, so this is a
   *  two-phase read, not a one-shot prop — an adapter renders an initial
   *  approximate `length` (the chord distance is a fine starting guess),
   *  measures the exact value off a ref inside a useLayoutEffect
   *  (which runs before the browser paints, so in the common case there's
   *  no visible flash at all — the approximation only matters for the
   *  dash math not dividing by zero on that first, unpainted pass), and
   *  stores it in state for the real render. React Flow's own
   *  BaseEdge renders the path itself rather than forwarding
   *  a ref, so this measurement needs its own hidden/duplicate
   *  <path> (or the adapter skips BaseEdge
   *  and owns the element directly) — a real adapter-side seam this
   *  proposal surfaces but doesn't fully design. */
  length: number;
  /** default "data" — this IS the preset selector (plays the role Pill's
   *  `state` plays), not a second axis alongside one — see traceStrokeStyle's
   *  own comment below for why an earlier draft's separate `state` prop
   *  was dropped as unjustified. */
  variant?: TraceVariant;
  /** The governed colour field itself, resolved via `trace.presets.ts` +
   *  `resolveField` keyed on `variant` — same mechanism as Pill's
   *  `lineColor` (PILL_PRESETS), not Port's direct STATE_TOKENS lookup. */
  strokeColor?: PaintToken;
  tone?: Tone;                    // same escape hatch as Pill/Port — overrides strokeColor
  /** marching-ants, data-only, opt-in (2026-09-14 lesson). The CSS
   *  `@keyframes` themselves are NOT this prop's job — `traceStrokeStyle`
   *  only returns the class NAME. SystemSketch owns its equivalent
   *  keyframes in its own `app.css`; bbox-ui's equivalent seam is
   *  `theme.css` (the file every consumer already imports for tokens) —
   *  the keyframes should ship there, not be left for each adapter to
   *  reinvent, or a React Flow Trace and a tldraw Trace could animate at
   *  different speeds. */
  animated?: boolean;
  /** "delayed" only — dotted end-to-end (SystemSketch's own default,
   *  `solidBeforePill: false`) vs solid-before/dotted-after the label.
   *  The mockup below illustrates the `true` branch; ship SystemSketch's
   *  own `false` default. DELIBERATE BEHAVIOUR CHANGE, flagged not
   *  silently carried over: SystemSketch's `solidBeforePill` is a single
   *  LIVE, GLOBAL presentation switch (one `atom`, every delayed cable on
   *  the board repaints together) — a board-wide viewing preference, not
   *  a per-cable fact. `splitAtLabel` here is a per-instance prop instead,
   *  because bbox-ui components don't have a "current document's global
   *  settings" concept to hang a shared atom off. A host that wants
   *  SystemSketch's exact board-wide toggle applies it by setting the
   *  same prop on every Trace instance it renders, itself. */
  splitAtLabel?: boolean;         // default false
  /** Where along the path the label sits — draggable is host state, Trace
   *  only reads the number. SystemSketch's own `clampPillPosition`
   *  (`connectionModel.ts`) clamps to `0.05..0.95`, not the full `0..1`,
   *  specifically to keep the pill off the terminals; Trace should keep
   *  that same clamp rather than allow a label to sit on top of a port. */
  labelPosition?: number;         // default 0.5, clamp to 0.05..0.95
  label?: ReactNode;               // the pill's content — Trace has no opinion on `z⁻¹`
  /** Trace's own abstract vocabulary, default "arrow" (every mockup below
   *  draws one) — each adapter translates it to its host's real mechanism:
   *  RF passes it through as `MarkerType.Arrow` (§5's correction — usable
   *  as-is) resolved by RF into a marker URL RF hands back as
   *  `EdgeProps.markerEnd`, which is what actually reaches `BaseEdge`; not
   *  a raw string RF itself consumes. tldraw uses the hand-rolled
   *  `` def straight from `SlantedArrowBody`. */
  markerEnd?: "arrow" | "none";
  strokeWidth?: number;
  vectorEffect?: "non-scaling-stroke";
}

/** Pure — no DOM. Computes dash mechanics (pattern, phase/offset) and, as
 *  data only, which CSS class name marching-ants needs — it never colours
 *  anything, and it never APPLIES the class itself (`className` is a
 *  value this function hands back, not a side effect it performs; the
 *  caller is the one that puts it on an element — see below). Colour is a
 *  SEPARATE resolution: `trace.presets.ts` (one `PresetSpec` per `variant`,
 *  keyed exactly like `PILL_PRESETS` is keyed on `state`) resolves
 *  `strokeColor` through `resolveField`. This mirrors Pill's REAL
 *  mechanism — Pill does NOT read `STATE_TOKENS` directly (that's Port's
 *  simpler path, a plain object lookup in `portDotStyle`); Pill runs
 *  `resolveField(lineColor, subject, PILL_PRESETS)` over a cascade, and
 *  Trace's `strokeColor` should cascade the same way. An earlier draft of
 *  this sketch had `traceStrokeStyle` return `stroke` too and a separate
 *  `state` prop alongside `variant` — dropped: two things both claiming
 *  to pick a colour is exactly what `assertDisjointPresets` (appearance.ts)
 *  forbids, and there was no real second axis to justify it. What
 *  DataCablePath/DelayedCablePaths hand-derived per branch, generalized to
 *  one function an adapter also calls directly when assembling React
 *  Flow's `BaseEdge` `style` prop for the single-stroke variants — see §3's
 *  worked example for the exact merge: `className` is pulled back OUT
 *  before the rest goes into `style` (it can never live inside a CSS
 *  object), and `strokeColor` is resolved through a real subject (so the
 *  caller's override isn't inert) and converted with Pill's own
 *  `paintColor()` — NOT bare `paintVar()`, which breaks on the real
 *  `"transparent"` member of `PaintToken` — before it becomes `stroke`.
 *  Three separate resolutions, deliberately never spread together. */
export function traceStrokeStyle(
  variant: TraceVariant,
  length: number,
  animated?: boolean,       // marching-ants only applies when variant === "data"
): { strokeDasharray?: string; strokeDashoffset?: number; strokeLinecap: "round" | "butt"; className?: string };

/** The multi-path SVG body — used directly by tldraw, and by React Flow
 *  only for the `delayed` variant (see §3). */
export function TraceBody(props: TraceProps): JSX.Element;

/** The label chip. Reuses `Pill` rather than inventing a twin — SystemSketch's
 *  own z⁻¹ pill drew in SVG only because its split-dash math lives in the
 *  same coordinate space; bbox-ui's Trace has no such constraint, so the
 *  label stays DOM like every other bbox-ui text slot (`Port`, `Pill`).
 *  Each host positions it through its own label portal:
 *  React Flow → EdgeLabelRenderer, tldraw → an HTMLContainer / absolute div.
 *  COLOUR CONTRACT (a gap in an earlier draft): `Trace`'s own `tone` is
 *  NOT automatic on the label — `Trace` and `TraceLabel` are two separate
 *  components/renders, so `<Trace tone="danger">` does not implicitly
 *  reach the pill. The §2 "tone=danger" mockup's matching red pill BORDER
 *  means the CALLER passes the same `tone` to both — `<Trace tone="danger"
 *  label={<TraceLabel tone="danger">retry × 3</TraceLabel>}>` —
 *  matches `packages/bbox-ui/src/portEdge.tsx`'s own `cascadeInto` (this
 *  exact repo, not a same-named vendored copy elsewhere that may have
 *  drifted), whose real prop list only ever cascades `textLayout`/optional
 *  `anchored` — `tone` isn't in it either. Trace follows that same
 *  precedent rather than inventing new cascade behaviour. One more thing
 *  the mockup got right only after a fix: Pill's label TEXT is always
 *  `text-foreground`, unconditionally (`pill.tsx`) — tone tints the
 *  border/fill, never the glyphs. The §2 mockup's red "retry × 3" text
 *  was wrong in an earlier draft; the SVG there now matches that real
 *  constraint. */
export function TraceLabel({ children, ...pillProps }: PillProps): JSX.Element;

Known gaps in this sketch, named rather than papered over with more pseudocode: a point-at-fraction sampler for an OPAQUE SVG path string (React Flow gives coordinates for its own bezier midpoint, but a generic `path` string needs its own sampling — likely another getTotalLength() + getPointAtLength() pair, alongside the length measurement); the actual React ref/effect lifecycle for the two-phase length read (whose ref, when it invalidates on a path change, what the hidden measurement element looks like for React Flow); and marker details SystemSketch's real code carries that aren't specified here — markerUnits="strokeWidth" and the transparent carrier path (systemSketchArrow.tsx:691-700) that keeps the head from collapsing into a blob at scale. None of these change the core/adapter split above; they're implementation, not architecture — real work for whoever builds this, not something worth designing further inside a proposal.
