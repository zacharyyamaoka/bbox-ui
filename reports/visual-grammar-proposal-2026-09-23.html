What the bbox-ui visual language should be

Not a survey and not a rewrite: the grammar written down as a closed vocabulary, four one-lane fixes where the field is genuinely ahead, one contradiction inside the tree resolved, and every taste call drawn so ignoring it is free.

answer1 · grammar2 · changes3 · stays4 · taste5 · stock parts6 · risks7 · decidesources

The answer

The language is three nouns, two structures, one family of marks and a two-axis camera — and most of it is already right. A Block is a definition; a Port is a named point on its wall; a Cable is the only line, and it carries a value. A Region is a Block wearing a frame whose corner card owns everything; an Arm is a stacked row inside it, every arm visible. Marks are paint that carries no value. The camera is granularity (simple · port · expanded) × footprint (hug · hold), and it never touches the document5,6,4.

What changes is small and specific. The peer report measured bbox-ui with the majority on 21 of 57 scenarios, with LabVIEW/Simulink on 18, alone on 15 — and behind on exactly four things, none of them a vocabulary problem1. Those four are changes 1, 2, 4 and 5 below. Change 3 resolves the one place the tree disagrees with itself (an execution edge at F9 vs 'never a cable') by making vertical position inside an expanded region mean source order — the only answer that is both cable-free and truthful, and it is only safe because the file is canonical1,3,5. Changes 6–8 give three 'alone' scenarios a drawing, name the one unnamed mark, and sketch the time-shaped family. Zero settled rules are reopened; one is watched (§6).

1 · The grammar in one page

Every mark, what it means, what it is not. exists is in the trunk today; new is this proposal, already drawn with variant 1 applied; sketch is a shape to look at, not a spec.

Nouns — three things exist on a board
exists
Block
A definition (grain 1). A header naming it, inputs on the left wall, outputs on the right, a footer when it has something to say.
a statement, an expression, an operator. Those are labels on a node or on a cable, never a box.
exists
Port
A named point on a wall where exactly one kind of thing happens: a value enters (left) or leaves (right). The dot is hollow until wired.
a coloured type (the type is printed on the label), a tunnel, a pin on a frame.
exists
Cable
The one line kind. A value, from one output to one input; fan-out is N cables off one port. Grey, elbow-routed, no arrowhead — direction is which wall it touches.
an execution wire, a control line, a message token. Nothing runs along a cable.
Structure — two ways blocks contain blocks
exists
Region
A Block wearing a frame. The corner card IS the block — it owns the id and every port; the frame is scope only and owns nothing. Kinds: loop, branch, group; proposed: try, with.
a frame with ports on its wall. A tunnel wall is LabVIEW's; the wall here has no id.
exists
Arm
A stacked row inside a region, one per suite: `if fast:` · `else:` · `case 'go':` · `except Timeout:`. A top rule and a fold chevron; every arm visible at once. Arms are nodes, so folding one never moves a sibling's blocks.
a card (Zach: 'control flow is not a card'); a tab that hides the other arms; a cable between arms.
exists
Mark
Paint that carries no value: a badge on a block, a pill on a cable, a tick on a wall. `break` · `continue` · `pass` · `mut` · `z⁻¹` · `iteration 3 of 7` · `edited`. A mark has no port, so nothing can wire to it.
a cable, a terminal, a node. If it could be wired it would be a port.
The wall — four states, from nothing to declared
exists
Crossing ring
Expanded region: a cable enters straight to the member; a hollow ring marks WHERE it crosses the frame. Positional, no id — the entry point is kept, no pin is minted.
an input tunnel. This is the wall state that keeps 'no input ports in expanded' honest.
new
Derived port
Port / opaque region: a port that exists ONLY because a cable crossed. Proposed: one per variable (not per producer), renameable, seated where its cable crossed. The dashed halo says 'derived'.
declared. Delete the crossing and it vanishes; a function's port stays.
exists
Collapsed dot
Simple face: one dot per wall standing for N pins — and it says which (`data-collapsed-ports="pose,gain,reset"`). Every cable still ends on a dot; simple is the many-to-one case, not the lawless one.
an exception to the pin-id rule. There is none.
exists
Declared port
Function block: drawn whether wired or not. `name: Type` printed on the label — ink, never colour. A grey-filled dot is a default the definition owns (F13).
coloured by type (Unreal/Unity/Blender/LabVIEW); a widget growing out of the port.
Cables — one kind, three dressings
exists
Named cable
A binding names a cable and adds no box (V2 — Simulink alone). An attribute path elides onto it (V6 `.gain`). Introducing or removing a name changes no block, port or edge.
a SET/GET pair, a pass-through node, twin name tags with the cable erased.
exists
Delayed cable
The one backwards cable: loop-carried state, dotted, wearing z⁻¹ (LabVIEW's shift register and Simulink's 1/z at once). Always drawn inside a region.
a control loop-back; a Set/Get pair hiding the carry (Unreal, Unity, Node-RED, n8n, Houdini).
exists
Mutation line
Receiver mutation (F7): a top-wall effect port and a dotted red line back to what changed, badged `mut`. State in on the left, the effect on top — never a second data cable pretending to be a new value.
an object-in/object-out pair (6 of 11). The receiver did not become a new value.
Views — a camera, not the document (granularity × footprint)
exists
Granularity: simple · port · expanded
How much of the inside is on screen, monotone. Blocks have all three; regions have port and expanded only (no simple — Zach, 2026-09-22). Source is the other side of the round trip, not a rung.
a fourth 'value' rung (there isn't one); a grain slider.
new
Footprint: hug · hold
Does the box keep its expanded size when its inside is hidden? Opaque = port's content at expanded's footprint — same size AND same seats. Today regions have it; proposed: Blocks too.
a fourth granularity. Hold at port content is the whole definition of opaque.
new
Plane: the root of the lens
Drill-in re-roots the projection at one definition and gives its expanded face the whole board; the breadcrumb is the definition path. No document state, no treeStack — the file is canonical and the graph re-derives.
sentinel Group Input / Output nodes; a copy of the body; a second geometry saved anywhere.
Laws — what the axes of the board mean
new
Left→right is data; top→down is order
Horizontal position is dataflow (time in the dataflow sense). Vertical position inside an expanded region is SOURCE ORDER, derived, never dragged — so two effect-only calls with no cable between them still read in the order they run (F9 / V13).
an execution cable (the imperative pair's answer); Max's hazard (position-as-order with a user who drags). The file is what makes the third answer safe.
exists
Never
No execution wire. No control cable. No sentinel nodes inside a definition. No box for a name. No tunnel on a frame wall. No colour-as-type. Every one of these is a field mechanism the rules above already exclude.
open. These are the closed doors that make the vocabulary small.

Three laws hold the sheet together. (1) Everything is a block, and a block has a wall: a region's interface is its corner card; a definition's interface is its declared ports; a region's port/opaque interface is derived, one port per value6,4,31. (2) Every cable ends on a dot, and a dot may stand for many pins but must say which — simple view is the many-to-one case, not an exception4. (3) Data and control never share a line: values ride cables, order rides position, exits ride marks5,1.

3 · What stays exactly as it is, and why

The settled list, each with the corpus evidence that it is right. This is what stops the proposal reading as a rewrite.

settledwhat the corpus says
The core imports no canvas engine; layout geometry travels, interaction geometry does notAll eleven are monoliths fused to their engine — 'how does Unreal draw a loop' had to be answered from screenshots. The freshest evidence for the split is the 705 field boards on this page: drawn by React Flow node types from bucket data in a day, with no engine in the data1,29.
Control flow is never a cable9 of 11 run the program on no execution wire; 8 of 11 draw no control line at all. The two dissenters are the imperative pair. Change 3 is what makes the rule hold for F9 without a cable1,2.
A region is ONE node; the corner card owns the id; the frame owns no idSimulink's For Iterator is a small block INSIDE the subsystem, the subsystem is the node with the ports — a corner card avant la lettre. MLIR: an operation owns its regions. LabVIEW's wall-owns-the-terminals is the design NI's own users asked to leave1,31.
Arms are `type: "arm"` nodes; break / continue / pass are Badge marksEvery arm visible is the thing LabVIEW could not draw once the input tunnels are gone. In the field a break is six different things (a wire back, a stub, a boolean into a wall, text in a field…); a cable implies a value and these carry none, so a badge is the only honest ink1,2,16.
Grain 1: a block is a definition, never a statement7 of 11 draw `+` as a box; the 17,192-px five-line function is what expression grain costs. Exposure measured: 15.7% of BAM core functions are operator-heavy — a real minority, concentrated in kinematics, and the number to watch32,1.
The file is canonical; the graph is a lens that re-derivesNI measured six of six participants introducing a bug while rewiring; that failure fires on graph edits, and a re-derived graph is never edited that way. It is also what makes changes 3 and 5 nearly free: order and the plane are both facts the projection already has1,24.
No output wall on a branch's corner card (V1); arms fan in at the consumerZach, 2026-09-02: yields 'get messy — then you don't know which of those ports are firing'. Unchanged in expanded. Change 2 is about what the same region shows in port/opaque, where a derived output IS an output — one per variable, which is the φ the asymmetry note already settled19,31.
A name is a label on the cable; a type is ink on the label, not colourV2: Simulink alone letters the name under the arrow; ten of eleven box it or refuse it. B8: four colour the port by type; the label carries the same information without a legend1,2.

4 · Where it is taste — the alternatives, drawn

Five decisions that are genuinely taste. Option 1 is the recommendation and is what §1 already shows; picking 2 or 3 is a one-line reply.

T1 · How a held Block shows its footprint

Change 1 needs a face. The region already has one (the P5 card with a footer); a Block can copy it or draw something lighter.

★ 1 · the region's card, footer states what is hidden · recommended, applied in §1

One face for blocks and regions; the footer is describeHidden, measured. This is what the trunk's opaque region already paints.

2 · port card at the corner, dashed ghost of the held bounds

Shows the two bounds literally (the field's model). Costs a second outline and reads as 'something is missing'.

3 · full card, hatched body

Blender's greyed-out group. Heavy ink for a state that should be quiet.

Pick 1: one face, one footer, and the region and the block stop being two designs.

taste

T2 · Where a derived port is named

Change 2 makes derived ports renameable. The name has to live somewhere a reader can find it without a dialog.

★ 1 · in place on the wall, with the ∂ halo · recommended, applied in §1

The label is editable where it is read (EditableText, as every port label is). The dashed halo is the only thing that says 'derived, and renameable'.

2 · sentinel in / out nodes inside the frame

The field's answer (6 of 11). Rejected: this is the input-tunnel wall NI's users asked to leave, drawn as nodes.

3 · inspector only, no mark on the wall

Cheapest. But a port whose name cannot be seen on the board is not an interface.

Pick 1: name it where it is read. The halo is 0.8px of ink.

taste

T3 · How an edited occurrence says so

Change 4 gives the drift a word; the badge is where the word goes.

★ 1 · amber `edited · <definition>` chip and a ↺ match action · recommended, applied in §1

Names what it drifted FROM, in the drift colour OriginBadge already uses for 'drifted'; the verb sits beside the state it repairs.

2 · a lock glyph, Houdini's way

Quiet and familiar to Houdini users; says nothing about which definition, and nothing about how to repair.

3 · Blender's user count with a ⇄ mark

Reads as 'shared by 2', not 'diverged'. The sibling report's #8 is already amending this badge in the other direction27.

Pick 1: the state, the parent, and the verb in one chip.

taste

T4 · Whether position-as-order gets any ink

Change 3 makes the y-rank a fact. The question is whether the board says so, or only the lint does.

★ 1 · nothing drawn; the y-rank is the order, a lint flags a violation · recommended, applied in §1

Zero ink. Consistent with 'no gutters' and with how source reads: order is position. The lint is the only place the rule becomes visible, and only when broken.

2 · faint ordinal rules between statements

Makes the rule legible to a stranger. Costs a line per statement — the gutter Zach keeps rejecting.

3 · a `then` chip on effect-only calls

Marks only the calls where order is the ONLY thing placing them (V13). Cheap, but a mark on the node for a fact about the region.

Pick 1, with 3 as the fallback if user testing shows the order is missed.

taste

T5 · The chrome of a plane

Change 5 needs a way back. Three shapes of the same fact.

★ 1 · the breadcrumb, and nothing else · recommended, applied in §1

editor/breadcrumb.tsx exists and is stock shadcn; the path IS the stack. Every segment is a click.

2 · a single Back chip on the board

Simulink's Back button. One level of memory; loses the path.

3 · tabs, one per open plane

Max's windows. State to manage, and it is the field's design, not a lens.

Pick 1: it already exists, and it is the honest shape of a projection root.

6 · Risks, and what would falsify this

A renamed derived port is a name the file does not hold.
The rename lives in the layout sidecar keyed to the VARIABLE, and re-derivation must find the same variable after an edit. Falsifier: rename `pose`, insert a blank line at the top of the file, re-derive — if the name is gone, the key is span-derived and this is the ρ problem again (0 of 14 ids survived exactly that on 2026-09-23)4. If it cannot be keyed to the variable, the rename should not ship.
Position-as-order makes free drag inside a region a lie, in every host.
Interaction geometry is host-owned, so each host must clamp or lint. Falsifier: if reviewers keep reordering members for readability and the lint fires constantly, order is not what vertical position wants to mean and the rule should retreat to effect-only calls (T4 option 3).
Hold costs canvas.
A held function at expanded size on a 30-block board spends area that the shrink used to give back. Falsifier: the sibling report's face-from-a-line-budget ceiling — if the budget keeps demoting held blocks to hug, hold is a per-viewer pin, not a default27.
Promote-by-variable needs the variable.
On a hand-drawn whiteboard region (SystemSketch) there is no binding name; the key falls back to the outer endpoint, which is today's behaviour. Falsifier: two producers inside a whiteboard region wired to one consumer still mint two ports. Acceptable; say so in the story.
A plane as a projection root has no memory.
Leaving the plane and coming back re-derives everything; a treeStack would have remembered scroll and selection. That is the price of not saving it. Falsifier: if Zach asks for 'go back to where I was' inside a plane, add per-viewer camera memory keyed to the root — still not a document field.
The settled rule I would watch, not reopen.
V1 — no output wall on a branch's corner card. It holds in expanded and dissolves in port/opaque by construction (a derived output IS an output wall). That is fine as long as it is said out loud; change 2 says it. The other rule worth a sentence: 'regions have no simple view' is right today and becomes a real question the day a region can hold (a held region with one dot per wall is a simple face).
